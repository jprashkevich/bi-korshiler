# Запуск контент-завода BIG Life: пошаговая инструкция

Время: около 1,5 часа на всё, из них 30–40 минут на обязательную часть (шаги 1–5).
Порядок важен: каждый шаг опирается на предыдущий.

Правило безопасности: ключи и токены вставляются только в Render (раздел Environment).
Не присылайте их в чаты, письма или документы. Если ключ где-то засветился, удалите его и создайте новый.

---

## Шаг 1. Ключ Claude API (10 минут)

1. Откройте console.anthropic.com и войдите (или зарегистрируйтесь на рабочую почту).
2. **Settings → Billing**: привяжите карту и пополните баланс. Для старта хватит $20–30.
   Ориентировочный расход завода — $15–30 в месяц при 2 постах в день.
3. **Settings → Limits** (по желанию): задайте месячный лимит расходов, например $50, чтобы не было сюрпризов.
4. **Settings → API Keys → Create Key**. Название: `biglife-content-factory`.
5. Скопируйте ключ (начинается с `sk-ant-`) во временную заметку. Он показывается один раз.
   Понадобится на шаге 3.

## Шаг 2. Telegram-бот и группа (10 минут)

1. В Telegram откройте **@BotFather** → `/newbot`.
   - Имя: `BIG Life Контент`.
   - Username: любой свободный, заканчивается на `bot`, например `biglife_content_bot`.
2. BotFather пришлёт **токен** вида `1234567890:AA...`. Сохраните его рядом с ключом Claude.
3. Там же отправьте `/setprivacy` → выберите своего бота → **Disable**.
   Это обязательно и именно до добавления в группу: иначе бот не увидит ваши ответы с комментариями.
4. Создайте группу, например «BIG Life — контент», и добавьте в неё:
   - бота;
   - SMM-щика;
   - себя и других согласующих.
5. Сделайте бота администратором группы (Управление группой → Администраторы → Добавить).
   Хватит минимальных прав.

ID группы и участников бот покажет сам после запуска (шаг 4).

## Шаг 3. Запуск на Render (15 минут)

1. Войдите на render.com через GitHub-аккаунт, у которого есть доступ к репозиторию `jprashkevich/bi-korshiler`.
2. Если Render попросит доступ к GitHub, разрешите доступ к репозиторию `bi-korshiler`.
3. Нажмите **New → Blueprint**. Выберите репозиторий `bi-korshiler` и ветку `claude/magical-mendel-vv08c5`.
   Ветку можно не выбирать, если код уже влит в основную ветку (`main`).
4. Render покажет, что создаст:
   - **biglife-content-factory** — фоновый воркер, план Standard;
   - **biglife-factory-db** — база Postgres.

   По тарифам это примерно $25 + $6 в месяц; точные цены смотрите на странице Pricing.
5. Render попросит заполнить переменные. Сейчас заполните:
   - `ANTHROPIC_API_KEY` — ключ из шага 1;
   - `TELEGRAM_BOT_TOKEN` — токен из шага 2.

   Остальные поля оставьте пустыми, их заполним позже.
6. Нажмите **Apply** / **Deploy Blueprint**. Первая сборка занимает 5–10 минут.
7. Откройте воркер → **Logs**. Сборка прошла, если в конце нет красных ошибок и процесс не перезапускается по кругу.

Пока ID группы не заполнен, завод ничего не генерирует и не тратит деньги. Бот только отвечает на команды.

## Шаг 4. ID группы и согласующих (5 минут)

1. Напишите в группе `/id`. Бот ответит двумя числами:
   - `chat_id` — ID группы, обычно начинается с `-100`;
   - `ваш user_id` — ваш личный ID.
2. Попросите каждого, кто будет согласовывать посты, тоже написать `/id`, и соберите их `user_id`.
3. В Render: воркер → **Environment** → заполните:
   - `TELEGRAM_CHAT_ID` — число из пункта 1 вместе с минусом;
   - `TELEGRAM_APPROVER_IDS` — `user_id` через запятую без пробелов, например `123456789,987654321`.
4. Нажмите **Save Changes**. Render перезапустит воркер за 2–5 минут.

Если на момент перезапуска уже больше 6:00 по Алматы, завод сразу соберёт посты на сегодня.
Если раньше — в 6:00.

## Шаг 5. Первый запуск и проверка (15 минут)

1. Если посты не пришли сами, напишите в группе `/run`. Через 3–7 минут придут 2 поста.
   Каждый состоит из альбома слайдов, ZIP-архива, подписи и блока с кнопками.
2. Проверьте первый пост:
   - Слайды читаются, нет обрезанного текста, фото подходит по смыслу.
   - Подпись — живая и без ошибок.
   - Блок «Проверка фактов»: откройте ссылку на источник и убедитесь, что утверждения там есть.
3. Попробуйте кнопки:
   - **Переделать**: бот попросит комментарий. Ответьте на его сообщение через «Ответить», например
     «Хук короче и смешнее, убери слово „исследование“». Через пару минут придёт новая версия.
   - **Другая тема**: соберётся пост на следующую тему той же рубрики.
   - **Одобрить**: пост одобрен. Пока Threads не подключён, бот напишет, что тред нужно опубликовать вручную.
   - **Отклонить**: пост снимается.
4. Если что-то пришло не так, сделайте скриншоты и пришлите мне с комментариями (см. шаг 9).

Обязательная часть на этом закончена: завод каждое утро присылает 2 поста.

## Шаг 6. Подключение Threads (30 минут)

Нужен доступ к аккаунту Threads BIG Life (логин и пароль) и личный аккаунт Facebook для входа в кабинет разработчика.

**6.1. Приложение Meta**
1. Откройте developers.facebook.com → **My Apps → Create App**.
2. Название: `BIG Life Content Factory`. Сценарий (use case): **Access the Threads API**. Завершите создание.
3. **Use cases → Threads API → Customize → Permissions**: добавьте
   `threads_content_publish` и `threads_manage_replies` (`threads_basic` уже есть).
4. Там же **Settings** — заполните три адреса одним значением `https://localhost/`:
   - Redirect Callback URLs;
   - Uninstall Callback URL;
   - Delete Callback URL.

   Нажмите **Save**.

**6.2. Доступ аккаунту BIG Life**
1. **App roles → Roles → Add People** → роль **Threads Tester** → введите username Threads-аккаунта BIG Life.
2. Войдите в Threads как BIG Life в браузере: threads.com → Настройки → **Аккаунт → Разрешения для сайтов → Приглашения** → примите приглашение.

Приложение может оставаться в режиме разработки. Для публикации в собственный аккаунт с ролью тестировщика проверка приложения в Meta (App Review), как правило, не нужна.

**6.3. Ключи приложения в Render**
1. В кабинете Meta: **App settings → Basic** → скопируйте **Threads App ID** и **Threads App Secret**.
   Берите именно Threads-версии, а не обычные App ID и Secret.
2. Render → воркер → Environment: `THREADS_APP_ID` и `THREADS_APP_SECRET` → **Save Changes**. Подождите перезапуск.

**6.4. Подключение через бота**
1. В Telegram-группе напишите `/threads`. Бот пришлёт ссылку.
2. Откройте её в браузере, где вы вошли в Threads как BIG Life, и нажмите **Разрешить**.
3. Браузер перейдёт на страницу `https://localhost/?code=...`, которая не откроется. Так и должно быть.
4. Скопируйте адрес из адресной строки целиком и отправьте **ответом** на сообщение бота. Код действует 1 час.
5. Бот ответит: «Threads подключён: @...». С этого момента «Одобрить» публикует тред автоматически,
   а токен продлевается сам раз в 30 дней.

## Шаг 7. Контент-план в Google Sheets (необязательно, 20 минут)

1. Откройте console.cloud.google.com и создайте проект `biglife-content`.
2. **APIs & Services → Library**: включите **Google Sheets API** и **Google Drive API**.
   Drive API пригодится на этапе 2.
3. **IAM & Admin → Service Accounts → Create**: имя `content-factory`, роли не нужны.
4. Откройте созданный аккаунт → **Keys → Add key → JSON**. Скачается файл.
5. Создайте Google-таблицу «BIG Life — контент-план».
   - Нажмите «Настройки доступа» и выдайте права **Редактор** email сервисного аккаунта (вида `content-factory@...iam.gserviceaccount.com`).
   - ID таблицы — часть адреса между `/d/` и `/edit`.
6. Render → Environment:
   - `GOOGLE_SHEET_ID` — ID таблицы;
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — всё содержимое скачанного JSON-файла (откройте его блокнотом и скопируйте целиком).

   Нажмите **Save Changes**, после этого удалите JSON-файл с компьютера.

Таблица заполняется сама: дата, рубрика, тема, источник и статус каждого поста.

## Шаг 8. Ежедневная работа (5–15 минут в день)

**Согласующий (утром, после 6:00):**
1. Прочитать 2 поста. Проверить по блоку «Проверка фактов», что цифры и выводы есть в источнике.
2. Нажать **Одобрить**, **Переделать** с комментарием или **Другая тема**.

**SMM-щик (после одобрения):**
1. Скачать ZIP из сообщения: в нём слайды в исходном качестве. Превью-альбом Telegram сжимает, его не используйте.
2. В Instagram: новая публикация → выбрать слайды по порядку (`slide-01`, `slide-02`…).
3. Подпись скопировать из сообщения «Подпись (скопировать)».
   Если нужна версия на казахском или узбекском, добавить её в конце подписи или первым комментарием.
4. «Расширенные настройки → Альтернативный текст»: вставить alt-текст из сообщения.
5. По желанию добавить музыку, геометку и соавторов (колаб).
6. Публиковать в рекомендованное время: утренний пост в 9:00, вечерний в 19:30.

Полезные команды в группе:
- `/run` — собрать посты вне расписания (тратит баланс Claude);
- `/id` — показать ID группы и пользователя;
- `/threads` — переподключить Threads.

## Шаг 9. Обратная связь в первую неделю

Чем точнее комментарии, тем быстрее я настрою тексты. Присылайте мне:
- скриншоты 3–5 лучших и 3–5 худших постов с объяснением, что не так (тон, хук, длина, визуал, фото);
- слова и формулировки, которые бренд не использует;
- темы, которые не подходят паблику, и темы, которых хочется больше;
- через 1–2 недели — охваты, сохранения и репосты из статистики Instagram по опубликованным постам.

По этим данным я обновлю голос бренда (`config/brand.md`), рубрики и критерии отбора тем.

## Шаг 10. Подготовка к этапам 2 и 3 (можно параллельно)

**Этап 2 — «Жизнь дворов» из отчётов в Google Drive**
1. Сложите отчёты о соседских активностях в одну папку Drive, например «BIG Life — отчёты для соцсетей». Отчёты могут быть документами, PDF или фото.
2. Выдайте этой папке доступ на чтение тому же email сервисного аккаунта из шага 7.
3. Пришлите мне ссылку на папку. Сам доступ я не получу, ссылка нужна, чтобы прописать ID папки.

**Этап 3 — Reels с вашим голосом (ElevenLabs)**
1. В ElevenLabs: **Voices → Add a new voice**.
   - **Instant Voice Clone**: нужно 1–3 минуты чистой речи.
   - **Professional Voice Clone**: от 30 минут, звучит заметно естественнее; доступен на платных тарифах.
2. Записывайте в тихой комнате, на хороший микрофон или телефон без шумодава, ровным тоном, как будто рассказываете соседу.
3. Создайте API-ключ: **Settings → API Keys**. Скопируйте **Voice ID** клонированного голоса.
   Ключ сразу вставьте в Render (`ELEVENLABS_API_KEY`), а Voice ID пришлите мне: он не секретный.

## Шаг 11. Перед публичным запуском

- **Шрифт.** TT Firs Neue в дизайн-системе — пробная версия (Trial). Купите коммерческую лицензию у TypeType
  и пришлите файл шрифта: я заменю его в `content-factory/templates/assets/`.
- **Переводы.** Попросите носителя казахского и узбекского языков проверить 5–10 первых кратких содержаний.
  Если нужно, я поправлю инструкции для перевода.
- **Аккаунт.** Проверьте, что в последнем слайде и подписи верно указан ник Instagram (`@big.life`).
  Если ник другой, напишите мне.

## Если что-то не работает

| Что происходит | Что сделать |
|---|---|
| Бот не отвечает на `/id` | Render → воркер → Logs: есть ли ошибки. Проверьте `TELEGRAM_BOT_TOKEN` (без пробелов). |
| Бот не реагирует на ответ с комментарием | Group Privacy не отключён: `/setprivacy` → Disable в @BotFather, удалите бота из группы и добавьте снова. |
| Кнопки отвечают «только ответственный» | Ваш `user_id` не внесён в `TELEGRAM_APPROVER_IDS`. |
| Пришло «Пост не удалось собрать» с упоминанием credit или balance | Пополните баланс в console.anthropic.com. |
| «Нет подходящих материалов» | Свежих релевантных тем мало. Это нормально изредка. Если часто — пришлите мне, расширим список лент. |
| Threads: «Код не принят» | Код старше часа или уже использован. Отправьте `/threads` заново. Проверьте, что Redirect URL в Meta — ровно `https://localhost/`. |
| Тред не опубликовался после «Одобрить» | Бот пришлёт причину. Чаще всего — не принято приглашение тестировщика или не добавлено разрешение `threads_manage_replies`. |
| Посты не пришли утром | Logs в Render: ищите «Ежедневный запуск». Можно запустить вручную командой `/run`. |
